# 🛒 Grocery Store Management & POS System

نظام متكامل لإدارة البقالة ونقاط البيع (POS) مبني باستخدام **Flutter**، يهدف إلى تنظيم عمليات البيع، المنتجات، المخزون، العملاء، الفواتير، الدفعات، الديون والتقارير من خلال تطبيق واحد بسيط وقابل للتوسع.

> **Project Status:** 🚧 قيد التطوير

---

## 📌 فكرة المشروع

تم تصميم النظام لتلبية احتياجات صاحب بقالة في إدارة العمليات اليومية، بدءًا من إضافة المنتجات وبيعها، مرورًا بإدارة المخزون والفواتير والعملاء، ووصولًا إلى متابعة المبالغ الآجلة والدفعات والتقارير.

الفكرة الأساسية:

```text
المنتجات
   ↓
نقطة البيع POS
   ↓
السلة
   ↓
الفاتورة
   ↓
العميل
   ↓
الدفع
   ↓
المخزون
   ↓
التقارير
   ↓
الديون والإشعارات
```

## ✨ المميزات

### 🧾 Point of Sale (POS)

- عرض المنتجات وإضافتها إلى السلة.
- البحث عن المنتجات.
- حساب الكميات والأسعار والإجمالي.
- إنشاء الفواتير.
- تحديث المخزون بعد إتمام البيع.
- دعم البيع النقدي والآجل والجزئي.

### 📦 إدارة المنتجات والمخزون

- إضافة المنتجات وتعديلها وحذفها.
- حفظ سعر البيع وتكلفة المنتج.
- متابعة الكمية المتوفرة.
- دعم Barcode.
- متابعة المنتجات منخفضة المخزون.
- الاحتفاظ بسعر وتكلفة المنتج وقت إنشاء الفاتورة.

### 📷 Barcode Scanner

يوجد مساران للباركود:

**Barcode داخل POS**
- الزر الموجود في شاشة POS مخصص للعمل الطبيعي داخل نقطة البيع.

**Barcode Scanner مستقل**
- زر Barcode عائم يفتح شاشة مسح مستقلة.
- الكاميرا تبقى مفتوحة بعد قراءة المنتج.
- تحديد الكمية.
- إضافة المنتج للطلب.
- العودة تلقائيًا للمسح التالي.

```text
فتح Scanner
     ↓
Camera ON
     ↓
Scan Barcode
     ↓
Find Product
     ↓
Quantity
     ↓
Add To Order
     ↓
Continue Scanning
```

### 👥 العملاء

- إنشاء وإدارة العملاء.
- الاسم، الهاتف، البريد الإلكتروني والملاحظات.
- البحث واقتراح العملاء.
- ربط العملاء بالفواتير.
- معرفة مشتريات العميل وديونه.
- العميل غير مطلوب في البيع النقدي المدفوع بالكامل.
- بيانات العميل مطلوبة للبيع الآجل أو الجزئي.

### 💰 الدفع والديون

يدعم:

```text
💵 نقدي
📒 آجل
🌓 جزئي
```

مثال:

```text
الإجمالي: 100
المدفوع:   40
المتبقي:   60
الحالة:    جزئي
```

### 🧮 سجل الدفعات

يسمح النظام بتسجيل دفعات متعددة لنفس الدين:

```text
فاتورة = 100

17/09 → 40
20/09 → 30
25/09 → 30

المتبقي = 0
الحالة = مدفوعة
```

### 📊 التقارير

التقارير المستهدفة مرتبطة بالبيانات الفعلية من SQLite:

- إجمالي المبيعات.
- عدد الفواتير.
- المبيعات اليومية والأسبوعية والشهرية والسنوية.
- النقدي والآجل والجزئي.
- إجمالي الديون.
- العملاء المدينون.
- المنتجات الأكثر مبيعًا.
- المنتجات الأكثر ربحًا.
- المنتجات منخفضة المخزون.
- الربح الإجمالي.

### 🔔 إشعارات الديون

يوجد زر إشعارات ثابت في رأس الصفحة يعرض عدد العملاء الذين لديهم مبالغ مستحقة.

صفحة الإشعارات تعرض:

- اسم العميل.
- إجمالي الدين.
- عدد الفواتير.
- البريد الإلكتروني.
- حالة الدفع.
- زر إرسال إشعار.

### 📧 البريد الإلكتروني

يدعم النظام تصميم خدمة لإرسال تذكيرات فعلية للعملاء الذين لديهم مبالغ مستحقة.

لا يجب وضع كلمات المرور أو مفاتيح API أو بيانات SMTP الحساسة داخل Source Code.

## 🔐 سلامة البيانات

يجب أن تتم عملية البيع كعملية ذرية باستخدام Database Transaction:

```text
BEGIN TRANSACTION
       │
       ├── التحقق من المنتجات
       ├── التحقق من المخزون
       ├── إنشاء الفاتورة
       ├── إضافة عناصر الفاتورة
       ├── تسجيل الدفعة
       ├── تحديث حالة الدفع
       ├── خصم الكمية من المخزون
       │
       └── COMMIT
```

وعند حدوث خطأ:

```text
ROLLBACK
```

بحيث لا يتم إنشاء فاتورة بدون تحديث المخزون أو تحديث المخزون بدون فاتورة.
